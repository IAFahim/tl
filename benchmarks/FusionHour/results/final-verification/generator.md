# Fusion generator experiment

The experiment adds no files under `src`. The generator is isolated in `benchmarks/FusionGenerate` and emits `Tl.FusionExperiment.FusedPulse` from `samples/Compiled/Timeline.cs` through `DeclarationReader`, `RegionAnalyzer`, and `WorkSlotMaterializer`.

## Supported semantics

The accepted operation grammar is deliberately closed: `Pulse.Decls.Pulse`, `Timeline<PulseTrack, PulseClip>`, `readonly record struct PulseClip(float Amount)`, and the exact normalized blend expression `first.Amount + (second.Amount - first.Amount) * t`. Each active work adds its amount in track order during forward movement and subtracts it during backward movement. Blend subtraction, multiplication, addition, and accumulator operations remain separate and ordered. Gaps execute no accumulator operation.

The generated API is `Start(uint tick = 0)`, `Stop(in Playback)`, scalar `Forward`/`Backward`, and `ReadOnlySpan<uint>` batch overloads. It preserves started/stopped validation before effects, raw ticks, cycle accounting and overflow before each tick's effects, `LastLoopFrame`, repeated ticks, wrapping, empty batches, and maximum raw ticks. It mints the current eight-byte little-endian `Playback` layout with `Unsafe.BitCast`; this is a prototype ABI dependency and not a public packaging design.

This is not a consumer-C# compiler. It does not support arbitrary payloads, blend laws, callbacks, state-dependent consumers, non-looping timelines, or general semantic analysis.

## Emission variants

| Options | Generated bytes | SHA-256 | Behavior |
|---|---:|---|---|
| `--batch scalar --backend tree` | 10,300 | `90d9b0e9942c98fb37e7e06682156b9f410d5a96650ea09906374365c6faf720` | Batch composes scalar direct-tree calls |
| `--batch carry --backend tree` | 18,651 | `452d4ad76e15bbbd45c0491aea136433fb01c45aec4d10d074cc988e42917499` | Batch carries playback locals and emits the balanced tree per tick |
| `--batch runs --backend tree` | 44,175 | `03688e55a58288fe4c771d38f4cef3e97854bda9abe7f96d375a94db9da79b14` | Batch dispatches once per maximal same-region run |
| `--batch carry --backend dense` | 18,043 | `19d4c1da93f89961fd18414f9e3182e0bdcec23b6cda400ca7580238c6f63cef` | Per-tick ordered operands in primitive static span data; duration <=4096 and at most three active works |

All four variants were independently emitted twice and compared byte-for-byte. `--self-test` passed rejection probes for changed blend arithmetic, changed clip shape, and unrelated input source. `git diff --check` is clean for the generator and generated artifact.

The generator footprint is 33,054 bytes of C#, 389 bytes of project file, and 2,845 bytes of documentation: 36,288 bytes total. These numbers and every generated artifact size are experimental costs separate from the unchanged public `src` budget.

## Measurements available at handoff

The scalar/tree and carry/tree variants passed 40,868 exact JIT comparisons covering forward/backward behavior, complete playback state, float bits, boundaries, gaps, wrapping, lifecycle rejection, overflow-before-effects, and scalar/batch composition. Carry/tree also passed the same 40,868 checks under NativeAOT. Runs/tree passed the JIT battery but lost to carry/tree and is rejected as a performance candidate.

On the stable 65,536-tick run, carry/tree batch medians were 1.344 ns sequential, 7.483 ns random, and 1.283 ns repeated, versus compiled-kernel medians of 10.471 ns, 19.545 ns, and 12.627 ns. Its measured hardware costs were 7.60 cycles sequential, 40.09 cycles random, and 7.08 cycles repeated; random traffic incurred 1.339 branch misses per tick.

Runs/tree batch medians were 2.844 ns sequential, 9.515 ns random, and 4.302 ns repeated, with 44,175 bytes of emitted source versus 18,651 for carry/tree. Earlier standalone JIT size measurements have uncertain build identity and are not used as evidence.

Dense batch medians were 1.401 ns sequential, 6.544 ns random, and 1.549 ns repeated. It improves the random case while regressing the other two, so carry/tree remains the balanced default. Dense precomputation uses separate non-inlined, non-optimized float operations and emits round-trip literals; generated JIT and AOT code should consume the same operand bits, while cross-architecture generator determinism remains unproven. Dense passed the fresh-build JIT battery with its embedded source hash. Dense NativeAOT parity and throughput were not measured.
