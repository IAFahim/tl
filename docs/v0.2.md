# v0.2 — the input/result split

**Status: implemented.** This document records the v0.2 API delta, the
input-immutability guarantee and the rationale for the result type owning the
hooks. Version 0.1.0 → 0.2.0 in `Tl.Runtime` (and `Tl.Gen`, aligned).

## 1. The change in one paragraph

v0.1 passed a single mutable `ref TData` through every hook: the consumer
struct was simultaneously read-only context (seeds, scales, tunables) and
live state (accumulators). v0.2 splits that parameter in two. An **immutable
input** (`in TInput`) carries context; a **mutable result** (`ref TResult`)
carries the live state. The split is a **full break**: every `ref TData`
signature in the public surface, the dispatch pointers and the binding caches
is gone, with no `[Obsolete]`, shims or parallel legacy overloads. Consumers
migrate by moving their context fields to an input struct and keeping the
state fields on the result struct.

## 2. API delta table

| v0.1 | v0.2 |
| --- | --- |
| `IForward<TTrack, TClip, TData>.Forward(ref TData data, in Tracks<...> tracks, in uint tick)` | `IForward<TTrack, TClip, TInput, TResult>.Forward(in Tracks<TTrack, TClip> tracks, in TInput input, in uint tick, ref TResult result)` |
| `IBackward<TTrack, TClip, TData>.Backward(ref TData data, in Tracks<...> tracks, in uint tick)` | `IBackward<TTrack, TClip, TInput, TResult>.Backward(in Tracks<TTrack, TClip> tracks, in TInput input, in uint tick, ref TResult result)` |
| `where TData : struct` on the hooks | `where TInput : struct` and `where TResult : struct, IForward<TTrack, TClip, TInput, TResult>, IBackward<TTrack, TClip, TInput, TResult>` |
| `Timeline.Forward<TData>(ushort, in Playback, ref TData, in uint)` + params twin | `Timeline.Forward<TInput, TResult>(ushort, in Playback, in TInput, ref TResult, in uint)` + params twin (Backward likewise) |
| `Timeline.Forward<TData>(ushort, in Playback, ref Cursor, ref TData, in uint)` + params twin | `Timeline.Forward<TInput, TResult>(ushort, in Playback, ref Cursor, in TInput, ref TResult, in uint)` + params twin (Backward likewise) |
| `Timeline.Forward<TData>(ushort, ref TData, params ReadOnlySpan<uint>)` | `Timeline.Forward<TInput, TResult>(ushort, in TInput, ref TResult, params ReadOnlySpan<uint>)` (Backward likewise) |
| `Timeline<TTrack, TClip>.Bind<TData>(ushort)` | `Timeline<TTrack, TClip>.Bind<TInput, TResult>(ushort)` |
| `Timeline<TTrack, TClip>.Forward<TData>(ushort, in Playback, ref TData, Span<TClip>, params ...)` | `Timeline<TTrack, TClip>.Forward<TInput, TResult>(ushort, in Playback, in TInput, ref TResult, Span<TClip>, params ...)` (Backward likewise) |
| `GeneratedTimeline<TTrack, TClip>.Forward<TData>(...)` — 8 methods | Same 8 methods with `(in TInput input, ref TResult result)` in the old data slot; ticks remain last |

Parameter order rules: the input/result pair sits **adjacent, in the old
`ref TData` slot** (input before result), and ticks stay last (C# requires
`params` in the final position). The hook callback order is
**(tracks, input, tick, result)**.

Unchanged in v0.2: `IBlend<TClip>`, `Playback`, `Cursor`, `Tracks`,
`TrackWork`, `TimelineBuilder`/`TrackRef`, the registry and lifecycle calls
(`Start`/`Stop`/`Destroy`/`Duration`/`IsValid`), and the `ITrackTables`
generation contract.

## 3. The input-immutability guarantee

The engine treats `TInput` as **read-only context**:

- It is passed `in` to every hook. A consumer cannot write through it — there
  is no API surface that would express a mutation, and the engine itself never
  assigns to it.
- It is not captured, cached or rehydrated by the dispatch layer; the same
  caller storage flows through every call of a run, bit for bit.
- Receipts prove it: `Receipt_InputUnchangedAfterForwardWalkAndBackwardRewind`
  (`tests/Tl.Core.Tests/SplitReceipts.cs`) walks a timeline fully forward and
  then rewinds it fully backward with a managed-free input struct covering
  many field kinds (byte, short, int, long, uint, ulong, float, double, bool,
  char, enum, nested struct, decimal) and verifies by `memcmp` that the input
  is bit-identical before and after both passes, in addition to field-level
  equality. The v0.1 contract — engine-owned code never writes consumer data —
  becomes a compiler-enforced one for the input half.

A secondary receipt, `Receipt_SameSeedSameAccumulationMatchesHandOracle`,
pins the semantics migration: when the v0.1 seed rode inside the mutable
struct, and in v0.2 it rides the input, the accumulated result is bit-identical
to a hand-computed oracle, and two runs with the same input produce the same
accumulation.

## 4. Why TResult owns the hooks

The hooks live on the **result** type, not the input:

```cs
public interface IForward<TTrack, TClip, TInput, TResult>
    where TResult : struct, IForward<TTrack, TClip, TInput, TResult>,
                    IBackward<TTrack, TClip, TInput, TResult>
{
    void Forward(in Tracks<TTrack, TClip> tracks, in TInput input, in uint tick, ref TResult result);
}
```

- **The result is the live state, and hooks are state transitions.** The
  callback receives `ref TResult result` and mutates it in place; the method
  that performs that mutation belongs to the type being mutated. This keeps
  the F-bounded pattern (`TResult : IForward<..., TResult>`) that v0.1 used
  for `TData`, so the hook always sees the concrete result type with no
  casting and no boxing.
- **The input is shared, inert context.** The same input value may feed
  several results or repeated runs; giving it behavior would imply it can
  change, which the guarantee above forbids.
- **Dispatch keys on the pair.** Binding caches are closed over
  `(TInput, TResult)`; the bridge mints one function-pointer set per closed
  pair per timeline entry. Which half owns the hooks therefore decides what
  `Bind<TInput, TResult>` can verify at compile time — putting them on the
  result lets the constraint `where TResult : struct, IForward<...>, IBackward<...>`
  prove hookability at the `Bind` call site, including under NativeAOT.

## 5. Dispatch changes under the split

- `Entry.Bind(Type input, Type result)` carries both types; the closure's
  `BindType` closes `BindEntryData<TInput, TResult>` via a two-argument
  `MakeGenericMethod` and installs `Bridge<TInput, TResult>`.
- Every function pointer in `Run`/`ScratchRun` gains the second byref
  (`delegate*<Entry, in Playback, in TInput, ref TResult, ReadOnlySpan<uint>,
  Playback>` and friends for the cursor/scratch/stateless shapes), still as
  typed managed byrefs — the defect-B design — so results in object fields or
  array elements stay tracked through dispatch, including results with
  managed fields (`Receipt_ManagedFieldResultMutatesThroughPointerDispatch`
  forces a compacting GC inside the hook and still observes the mutation).
- `BindingCache<TInput, TResult>` and `ScratchCache<TTrack, TClip, TInput,
  TResult>` are keyed on the closed pair; each minted pair gets its own
  copy-on-write run table.
- The AOT guard message now names `Bind<TInput,TResult>` as the explicit
  registration call.

## 6. Migration sketch

```cs
// v0.1
struct Health : IForward<T, C, Health>, IBackward<T, C, Health>
{
    public float Seed;   // context, mutated never
    public float Value;  // state, mutated always
    public void Forward(ref Health data, in Tracks<T, C> tracks, in uint tick) { ... }
}

// v0.2
readonly struct HealthInput(float seed) { public readonly float Seed = seed; }

struct HealthResult : IForward<T, C, HealthInput, HealthResult>,
                      IBackward<T, C, HealthInput, HealthResult>
{
    public float Value;
    public void Forward(in Tracks<T, C> tracks, in HealthInput input, in uint tick, ref HealthResult result) { ... }
    public void Backward(in Tracks<T, C> tracks, in HealthInput input, in uint tick, ref HealthResult result) { ... }
}

// usage
Timeline<T, C>.Bind<HealthInput, HealthResult>(id);
var input = new HealthInput(100f);
var result = new HealthResult { Value = input.Seed };
var pb = Timeline.Start(id);
pb = Timeline.Forward(id, in pb, in input, ref result, 0u, 1u, 2u, 3u);
```

Pure accumulators with no context define a trivial empty input struct in
consumer code (the test suites use a test-local `NoInput`; it is a fixture,
deliberately not part of the public API).

## 7. Verification

- `tests/Tl.Core.Tests` and `tests/Tl.Gen.Tests` fully green, including the
  three new split receipts and the updated zero-allocation checks
  (warm playback still allocates 0 B across single/batch/cursor/scratch).
- `tests/Tl.Aot` republished under NativeAOT (`PublishAot`,
  `IlcInstructionSet=native`) and executed green: explicit
  `Bind<TInput, TResult>`, hub/cursor/scratch/stateless paths, generated
  tables, unbound and wrong-closure failure modes, printed checksums.
- A registration growth defect found while gating this change (slot/run
  arrays doubled on every registration until `length * 2` overflowed int)
  is fixed in `Timeline.Register`, `BindingCache.Install` and
  `ScratchCache.Install`; growth is now geometric only when an index does
  not fit, and indexes are bounded by `Timeline.None`.
