# v1.0.0-alpha.3 candidate

Alpha.3 replaces per-timeline playback facades and runtime IDs with generated catalog queries over component columns. One timeline can contain heterogeneous track and clip pairs, and every track binds an explicit typed job. All rows in a query share one caller-owned game clock while each row retains independent asset, position, and loop cycle.

This document describes the candidate. A release tag exists only after every open gate in issue #35 passes on one exact reviewed commit.

## Public C# shape

```cs
public readonly struct DamageJob : ITimelineJob<DamageTrack, DamageClip>
{
    public static void Execute(
        in Frame<DamageTrack, DamageClip> frame,
        in Resistance resistance,
        ref Health health)
        => health = new(
            health.Value - frame.Direction * frame.Clip.Amount
                * frame.Track.Multiplier * resistance.Scale);
}

public readonly partial struct Attack : ITimeline
{
    public static void Define(scoped Builder builder)
    {
        var animation = builder.Track(new AnimationTrack()).Use<AnimationJob>();
        var damage = builder.Track(new DamageTrack(2f)).Use<DamageJob>();
        builder.Clip(animation, new AnimationClip(2f, 1f), 0u, 20u);
        builder.Clip(damage, new DamageClip(10f), 5u, 6u);
    }
}

public readonly struct CombatRows;

public readonly partial struct Combat : ITimelineCatalog
{
    public static void Define(scoped CatalogBuilder builder)
    {
        builder.Schema<CombatRows>().Asset<Attack>();
    }
}

var states = new[] { new Combat.State(Combat.Asset.Attack) };
var query = new Combat.Query().CombatRows(states, poses, resistance, health);
query.Tick(200_000u, 3);
query.Tick(200_003u, -3);
```

There is no runtime `Build`, `Compile`, `InMemory`, `Bind`, registration ID, `Start`, `Stop`, or `TrySeek`. Normal Roslyn and supporting IDE builds generate the code automatically.

## Behavior

- Each requested step selects every row without user effects, executes typed operation stages, then commits each selected row once.
- Authored A→B→A order is preserved. Reverse movement executes the exact reversed occurrence order.
- Finite assets clamp independently. Empty routes, gaps, empty definitions, completion, and zero delta are no-ops.
- Nonempty loops use unsigned local position and signed cycle with explicit wrapping arithmetic.
- `Tick(G,+N)` emits `G..G+N-1`; `Tick(G,-N)` emits `G-1..G-N`.
- One active clip is borrowed. Two active clips resolve through `Blend` into one frame.
- Frame direction derives from one-byte flags and consumes no stored integer.
- Jobs borrow unmanaged `in` and `ref` component columns. Alpha.3 rejects `out`.
- Schema construction rejects mismatched lengths, invalid routes, and prohibited writable aliases before effects.
- A user exception preserves its executed effect prefix and prevents state commit for that step.

## Compiler and packaging

The C# frontend now consumes `Tl.Compiler`'s validated language-neutral ordered plan. Regions, occurrence order, payload storage identity, and deduplication have one semantic implementation below the backend.

`Tl.CSharp` remains the recommended single package. It depends only on `Tl.Runtime` at application runtime and embeds:

- `Tl.Gen.CSharp.dll` and `Tl.Compiler.dll` under `analyzers/dotnet/cs`
- the explicit net10 export tool, compiler, and private Roslyn dependencies under `tools/net10.0/any`

Package-only JIT and NativeAOT checks reject those compiler assemblies from application output. `TlGenExport` produces deterministic physical generated source, a manifest, and a report with generated, static, neutral payload, schedule, and state size facts.

`Tl.Gen.C` retains the previously qualified C ABI v2 and consumes the versioned compiler package. It does not emit alpha.3 heterogeneous catalogs. The C catalog migration, designer GUI, and backend repository extraction remain separate work.
