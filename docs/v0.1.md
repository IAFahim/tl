## 1. Scope and freeze rule

Use the [README](../README.md) and [semantics](semantics.md) as the current
product contract. Earlier API mocks and research notes remain historical.

Freeze the three consumer hooks, `uint` time, half-open windows, authored work
order, per-work state, 8-byte playback and caller-owned state. Preserve float
operation order and bitwise parity for the fixtures that require it. Keep the
runtime region-table algorithm, optional cursor, blend-sized scratch and
opt-in storage deduplication.

A freeze does not preserve truncation, invalid memory lifetimes, races or missing
validation. Repair those with focused tests and a measured before/after result.
If a safety repair costs time, record the cost instead of retaining the defect.

The earlier sub-1 ns extraction gate is explicitly replaced for this phase by
correctness, packaging and measured regression gates. The target is still unmet;
there is no proof that it is impossible. No float reassociation, sampling-only
substitution or cross-repository result may be presented as meeting it.

Out of scope: blob formats, merging iutq, new hook families, Unity editor UI,
WebAssembly integration, a new timeline DSL, and another broad algorithm search.
Do not introduce async, pooling or unsafe indexing merely to call the library fast.

## 4. Fix before freezing

### A. Preserve duration width

Runtime compilation currently narrows the final cut to `ushort`; `Entry.Duration`
and public `Timeline.Duration` are also `ushort`. This contradicts the `uint`
time contract. Widen the whole metadata path, not just the public return type.

```cs
// In Entry:
public required uint Duration { get; init; }

// In Compile:
Duration = regionStarts[^1],

// In the public hub:
public static uint Duration(ushort index) => Live(index).Duration;
```

Test 65,535, 65,536, 70,000 and `uint.MaxValue` end cuts, empty duration,
completion and looping normalization. Clip/track/index capacities remain separate
checked limits. Audit arithmetic before casts, including consumer-token exhaustion.

### B. Keep managed references valid through dispatch

The hub currently converts `ref TData`, `ref Cursor` and caller scratch into raw
pointers. A `ref` argument may point into a movable object or array, and a consumer
hook may allocate or trigger GC. `TData : struct` also permits managed fields.
The source comment saying “stack-pinned” does not establish pinning.

Prefer a bridge that carries actual managed byrefs throughout the call. One
candidate shape is a per-`TData` binding cache with a typed function pointer:

```cs
// Sketch: the bridge still knows the track/clip closure when it is installed.
internal unsafe readonly struct Run<TData> where TData : struct
{
    public readonly delegate*<Entry, in Playback, ref TData,
        ReadOnlySpan<uint>, Playback> Forward;
}
```

Carry `ref Cursor` as a managed byref too. Keep `Span<TClip>` on the typed scratch
path, or establish a valid pin for the entire raw-pointer use. A managed delegate
allocated once during binding is another candidate if needed; measure it.
`unmanaged`, `GC.KeepAlive` and a no-allocation benchmark are not pinning proofs.
The [Unsafe.AsPointer documentation](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.compilerservices.unsafe.aspointer?view=net-10.0)
explains why pointers into GC-managed objects require pinning.

Test data/cursors in object fields and array elements, reference-containing
consumer structs, heap scratch, allocating callbacks, forced compacting GC and
separate-buffer reentrant calls. Verify mutations reach the original caller.
Run the supported combinations under JIT and published AOT. Document the chosen
lifetime argument; passing a stress test alone is not that argument.

### C. Validate the typed scratch closure

The typed `Timeline<TTrack,TClip>.Forward/Backward` scratch overloads fetch a
live global entry without establishing that it belongs to that track/clip pair.
A consumer implementing multiple hook pairs can make binding succeed while the
scratch element type is wrong. Apply the same closure check as explicit `Bind`:

```cs
var entry = Timeline.Live(index);
if (entry.Payload is not Tables)
    throw new ArgumentException("Timeline belongs to a different track/clip pair.",
        nameof(index));
```

Do this before interpreting scratch or invoking hooks, in both directions.
Test wrong closures with equal-sized and different-sized clip types, a consumer
implementing both closures, zero blends and undersized scratch.

### D. Publish complete bindings

`Entry.Install` publishes a grown array before filling its slot and mutates
multi-pointer `Run` values while readers are unlocked. A lock around only the
writer does not make those struct reads atomic.

For the existing representation, an immutable snapshot is a simple starting
point. Validate token bounds/capacity before this block:

```cs
lock (_bindGate)
{
    var current = _runs;
    if ((uint)token < (uint)current.Length && current[token].IsBound)
        return;

    var next = new Run[Math.Max(token + 1, current.Length)];
    current.CopyTo(next, 0);
    next[token] = run;
    Volatile.Write(ref _runs, next);
}
```

Published arrays are never mutated or returned to a pool. Readers take one
`Volatile.Read` snapshot. Adapt this if B changes the cache representation.
Cold binding may allocate. Measure retained storage as well as dispatch time.
Audit registry slot publication similarly. Define whether `Destroy` allows an
already-started call to finish; test the documented behavior. Separate callers
own separate playback, cursor, consumer and scratch state.

### E. Validate track-handle ownership

`TrackRef` currently contains only an index. A default handle can name track zero,
and a handle from another builder with the same index is not rejected. A
`ref struct` lifetime restriction does not establish builder ownership.

Carry an owner identity in the authoring-only handle and check it when adding a
clip. For example, a non-null reference to the builder's `Authoring` object plus
the index permits `ReferenceEquals(track.Owner, _state)` validation. Reject default
and foreign handles; test two builders in the same stack scope and nested builds.
This adds cold authoring metadata, not per-tick work.

### F. Separate a general generator from a benchmark kernel

`EmitFrozen` currently targets `FrozenSink` fields and known fixtures. Its
full-bake path has a duration limit of 1,024. Its emitted public movement methods
also lack the runnable-playback check present in the generic/runtime facade.
Neither the fixture nor its timing proves arbitrary user hooks are supported.

Extract a general definition → validation → plan → C# adapter pipeline first.
Generate typed tables and use the checked playback contract. Keep the optimized
bake only for shapes whose equivalence is established; route unsupported shapes
to the general generated path or return a clear generation diagnostic.

Validate default/stopped playback before entering an internal optimized kernel.
Preserve empty-tick callback suppression, authored work order, blend calls and
arbitrary observable hook effects. Do not replace an inactive operation with
“add zero” unless the supported numeric/consumer contract proves equivalence.
Use exact float receipts where required, including signed zero and non-finite
values if supported. No reassociation into multiple accumulators.

Test independently authored payloads, tracks and consumers in another assembly,
including consumers with side effects beyond a float sum. Add loop, sparse-gap,
reverse and large-duration cases. Bake selection must obey an explicit code/data
size budget, not allocate duration-squared tables for arbitrary `uint` timelines.

## 5. Keep the completed optimization decisions

| Experiment | Production action |
| --- | --- |
| Persistent cursor | Keep optional, with owner/start-position validation and search fallback |
| Blend scratch | Keep `MaxActiveBlends` sizing, 4,096-byte automatic stack limit and caller-buffer overloads |
| Prefix cut counts | Rejected. Keep research receipts; remove experimental switches/count tables from the extracted hot path |
| Storage deduplication | Keep optional, default off; express it as a per-build option, not a mutable process-global benchmark switch |
| Skew-balanced search trees | Rejected. Do not reopen without a new workload or evidence |

For dedup, share payload storage without merging authored clip identities, states
or callback multiplicity. Resolve hash collisions with equality. Preserve the
identity-map-free path when disabled. Avoid promising deterministic byte-level
dedup for unspecified struct padding; document the supported payload contract.

After safety fixes, only investigate a performance change if the extraction
introduces a measured regression. Do not add SIMD, parallel accumulators,
function-pointer layers or branchless rewrites on intuition alone.

## 6. Ordered implementation batches

Complete one batch and its checks before starting the next. Keep changes small
enough to review; do not mix the whole extraction with algorithm replacements.

1. **Record the baseline.** Confirm HEAD and a clean working tree. Run the README
   receipt commands. Record exact SDK/runtime, CPU and source hash. Retain current
   benchmark baselines; do not refresh golden outputs to hide a mismatch.
2. **Extract the core.** Create the solution and `Tl.Core`; move the contract and
   implementation without fixture types. Add tests, resolve A–E, remove rejected
   prefix plumbing, and make dedup a per-build option. Compile the README consumer
   against the separate library assembly. Pin the public API in an approval file.
3. **Extract generation.** Create `Tl.Gen`; move reusable Waffle emission behind
   the adapter boundary and resolve F. Keep fixture construction in benchmarks.
   Compile generated output in a separate sample/test project and compare its
   execution with an independent simple oracle and runtime compilation.
4. **Integrate build and AOT.** Make regeneration respond to input, adapter and
   generator changes. Write outputs under the consuming project's `obj` directory;
   do not share writable generated files across parallel builds. Test clean and
   incremental builds, deletion/recreation, deterministic output and concurrent
   builds. Add a published AOT smoke app using explicit `Bind<TData>` and the real
   public runtime API, not only the frozen fixture harness.
5. **Finish v0.1.** Repoint current-engine benchmarks to project references so
   there is one implementation. Keep legacy helpers in benchmark-only files.
   Run the release checks below, update README status, record known limits and
   freeze the implementation. Produce reviewable package artifacts and release
   notes; do not publish packages or tag a release as part of extraction.

Existing “generate if missing” build targets are insufficient: changing the
emitter with old generated files present must rebuild the output. Use declared
inputs/outputs or equivalent content/version tracking. No runtime code generation
or reflection fallback may be required for the explicit AOT path.
