# Memory and performance

## Quantities

`tl` reports costs separately so one small number cannot hide work elsewhere.

| Quantity | Meaning |
| --- | --- |
| Product source bytes | UTF-8 production source contents plus relative paths |
| Generated source bytes | UTF-8 C# emitted for a consumer's timelines and catalogs |
| Neutral payload and schedule bytes | Serialized semantic data before target binding |
| Static data bytes | Target `sizeof` sum for unique emitted track and clip values |
| State bytes | One generated catalog state value per row |
| Managed allocation | Warm execution allocation measured by receipts and BenchmarkDotNet |
| JIT or NativeAOT code bytes | Machine code for generated timeline and query methods |
| Assembly or executable bytes | Complete target artifact, reported separately from generated code |

`TlGenCompile.report.txt` records every generated artifact and each timeline's tracks, clips, operations, slots, regions, occurrences, unique schedules, unique payloads, neutral bytes, generated bytes, static bytes, and catalog state bytes. Generated definitions expose shape constants without constructing a registry or runtime authoring graph.

The alpha.3 catalog state is 24 B on the qualified x64 target. It stores catalog-local asset, local position, signed cycle, and bounded pending selection. The external game tick remains caller-owned. Query values borrow caller state and component columns and retain no entity data or frame queue.

## Warm execution

The medians in this section are v1.0.0-alpha.3 records from the qualified release run; the alpha.3 authored surface was removed under [issue #65](https://github.com/IAFahim/tl/issues/65), the data-authored facade warm path was later removed under [issue #104](https://github.com/IAFahim/tl/issues/104), and the shipped contract is the typed playback lane of [docs/typed-playback-lane.md](typed-playback-lane.md). These records are retained as history; current-surface receipts are the lane parity, capacity, and 0 B measurements in that document.

Generated definitions are immutable static data. A .NET query validates mutable routes, selects each row, calls concrete typed jobs in authored stage order, and commits each selected state. The hot path contains no reflection, boxing, delegate dispatch, runtime compilation, managed registry, lock, or managed allocation.

The retained three-process full-query medians on the i9-14900K reference host are:

| Shape | Generated time | Allocation |
| --- | ---: | ---: |
| 1 track | 1.804 ns/tick | 0 B |
| 3 tracks, A-B-A | 3.754 ns/tick | 0 B |
| 16 tracks | 21.230 ns/tick | 0 B |
| 256 tracks | 34,250.868 ns/tick | 0 B |
| Internal gap | 1.997 ns/tick | 0 B |
| Two-clip blend | 2.555 ns/tick | 0 B |
| Three input columns | 2.256 ns/tick | 0 B |
| 256 rows, 5 assets | 34.650 ns/entity-tick | 0 B |

The `<3 ns` target holds only for the named 1-track, gap, blend, and three-input shapes. It does not hold for A-B-A, 16 tracks, 256 tracks, or mixed routing. The 256-track kernel exceeds the 32 KiB fusion budget and uses the general staged scheduler; its size and branch cost are a measured open performance problem in [issue #10](https://github.com/IAFahim/tl/issues/10).

[The complete alpha.3 shape matrix](../benchmarks/Alpha/results/v1.0.0-alpha.3-shape-matrix/README.md) retains three raw BenchmarkDotNet processes, ranges, tiering comparison, grouped PMU counters, FullOpts assembly, code-size fixtures, checksums, receipts, and reproduction commands. Branch misses are low for small shapes, so a blanket branch-likelihood hint is not supported by the evidence.

## Data-authored native assets

`TimelineAsset.Load` validates one TLB1 byte sequence and copies it into a single block from `NativeMemory.AlignedAlloc`, sized up to the next multiple of 64 B and aligned to 64 B. The block layout is a 48 B header, a pair table, a stage table, one step program per stage, and the frame slots. Every section offset is 8-aligned; every frame slot is 16-aligned with a pair-declared stride, and each slot carries the track value, first and second clip values, clip window, blend-factor window, and authored track index. Validation checks magic, version, byte size, sorted pair keys, monotone stages covering the duration, and in-bounds aligned slots before any effect; the block is immutable after publication.

The owner disposes the asset exactly once; `Dispose` swaps the pointer atomically and frees the block. A `TimelineRef` holds the raw block pointer without a lock or reference count, so every reader of an asset must finish before its owner disposes it. Each `TimelineComponent` retains one such reference plus its own local position and signed cycle.

Track and clip identity is a 64-bit pair key over the closed build-time type universe. The generated module initializer installs consumers into the process-global `PairTable` once under a lock; dispatch resolves the published table lock-free and never mutates it. Warm lane playback retains `0 B` of managed allocation: `tests/Tl.Alpha` proves 100,000 x 256-row lane applies at zero retained bytes, and `benchmarks/Alpha --verify` repeats the assertion per shape with identical oracle checksums.

The typed lane enforces a strict per-call pointer lifetime. `TimelineLane<T>` is a `ref struct` holding the caller's position span by value; every `Apply` derives its interior pointers from the borrowed spans and never lets one outlive the synchronous call. A compacting GC relocating caller arrays between calls is safely observed on the next call through the span fields.

### Lane bind tables

Cold bind work is per (pair, asset): `BakedLane<TTrack, TClip>.Bind(asset)` measures the forward and backward float effect tables once — `max(1, duration)` floats each, `NativeMemory.AlignedAlloc`, 64 B-aligned — validates position purity by re-measuring every position at two cycles and two column seeds, and publishes by pointer swap, freeing the previous tables on rebind. Table bytes are `2 * max(1, duration) * sizeof(float)` per bound pair (512 B for a 64-tick asset, reported by `tests/Tl.Alpha`). The measurement itself runs through the cold executor on stack-resident scratch columns; nothing from the bind survives except the two native tables and the duration/looping scalars.

### Shared bind cache (removed surface, retained receipts)

The alpha.6 facade's process-global shared bind cache — 256 direct-mapped four-way slots, each holding one immutable bind record of 656 B (about 164 KiB of bounded native static data) capturing asset address, column key-sequence hash, consumer and kernel registration phase, bound consumer mask, column bindings, refresh pairs, pair chain heads, and the resolved kernel pointer — was removed with the facade and kernel catalog under [issue #104](https://github.com/IAFahim/tl/issues/104). Its warm-lookup law (lock-free volatile read chain, compare-exchange publication, immutable records, dispose generation) is preserved below as the historical record of that surface; the lane bind tables above are its successor.

Warm lookup is a lock-free volatile read chain (slot seal, identity fields, phase) with no lock, no managed reference, and no allocation on any tick path. A miss runs the per-construction bind exactly as before and then publishes its result through a single compare-exchange claim; a losing claimer never waits, rebinds per construction, and may publish a duplicate identical record on another free way of the same group. Records are immutable after publication, so no reader observes a partial state. A lookup matches only when the record's asset address, column key-sequence hash, `TimelineQuery.Find` pointer, `PairTable` consumer count, kernel registration count, and dispose generation all equal the current values. The consumer count, kernel registration count, and `Find` pointer are captured before the bind walk; the consumer count and the kernel registration count only grow, so any consumer or kernel installed after that capture makes the stored value stale and the next construction rebinds, picking up the prepended chain head or the late-registered kernel. Because registered kernels are never removed, an unchanged registration count proves a publish-time negative lookup still valid: a stable-negative identity — an unregistered asset in a process where kernels exist — re-runs no content hash across constructions, where the lookup previously re-paid the full per-asset hash every time. A restored record re-reads its seal and generation around the payload copy and rebinds when either changed, so a record invalidated by a concurrent `Dispose` is never adopted, and the lookup releases the claim of any generation-dead way it walks, so four stale records cannot pin a group against republication. `TimelineAsset.Dispose` advances a global generation and reclaims the disposed address's slots, so an asset reusing the address can never observe the previous asset's record. The ownership rule is otherwise unchanged: the asset owner must quiesce rows before `Dispose`, and the generation advance makes every record keyed to the disposed address dead at that instant. Non-uniform row sets, row sets over more than 16 pairs, and the `TickUnmanaged` caller-owned state path do not participate; they keep per-construction behavior.

Rebuilding 1,000 single-row queries per frame over the same rows and columns, looping asset, one consumer, one writable column (i9-14900K, .NET 10.0.12, pinned core, median of 15 after 5 warmups, interleaved baseline and candidate processes, three runs per build with the median run shown, `GC0/1 = +0` in every lane, effect receipts byte-identical across every lane, regime, and build). Before the kernel-registration phase the kernel regime decided where the lookup cost landed; per-construction binding before the shared cache itself measured 494.4 / 1,784.0 / 42,004.4 us/frame. Each cell shows baseline → candidate:

| Kernel regime | 128 B | 3.6 KB | 112 KB |
| --- | ---: | ---: | ---: |
| No kernel registered (lookup never runs) | 166.2 → 156.3 us | 184.9 → 178.3 us | 191.9 → 188.5 us |
| Registered, identity unbound | 444.5 → 138.5 us | 1,812.5 → 157.7 us | 43,733.8 → 183.4 us |
| Registered, identity kernel-bound (hash runs once) | 145.4 → 143.6 us | 159.9 → 163.9 us | 183.6 → 180.7 us |

The unbound regime collapses to the kernel-less-process cost because the content-hash lookup now runs once at publication instead of once per construction — 3.2x, 11.5x, and 238x on the 136 B, 3,648 B, and 114,752 B blocks. The kernel-less and kernel-bound regimes are flat within run noise; the candidate's warm restore adds one registration-count compare and two seal/generation re-reads per construction. A kernel-bound identity still runs the content-hash lookup exactly once per process. The control lane (one construction followed by 1,000 ticks of the same query) measured 23.1-23.7 / 42.5-59.8 / 71.7-78.6 us depending on regime. The residual per-construction cost is query construction and column validation, not binding. The one-shot read lane (`Timeline.Query<T,C>` / `FrameQuery`) and the single-row fast path are unchanged; a restored query takes the same fast path a previously ticked query takes.

## Code and data size

The retained code-size fixtures report:

| Tracks | Generated C# | Static data | FullOpts JIT code | NativeAOT code |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 10,187 B | 8 B | 2,848 B | 2,078 B |
| 16 | 38,686 B | 128 B | 18,328 B | 9,900 B |
| 256 | 298,075 B | 2,048 B | 87,959 B | 75,547 B |

Those consumer outputs are separate from the product source budget. Coverage commit `9b1807686b9035b19a63133cd4f416ab1721e29b` measured 231,796 B of production source plus paths against the 250,000-byte cap in force at that commit; the cap is 300,000 bytes today and `benchmarks/source_budget.py` is authoritative. The neutral plan deduplicates exact type identity plus canonical payload bytes; the C# frontend currently deduplicates identical normalized type and expression bindings. A hash match never establishes equality.

The representation lower bounds are explicit. A finite position over `0..D` requires at least `ceil(log2(D + 1))` bits. Choosing among `A` catalog assets plus empty requires at least `ceil(log2(A + 1))` bits. These bounds do not erase alignment, pending selection, stage identity, or the requirement to execute every observable effect.

## Unity ownership

Unity materialization emits immutable timeline data, one catalog state component, enableable schema markers, typed logical-slot components, selectors, operation jobs, and commit jobs. Scheduled jobs carry component handles and values supported by Entities and Burst; they never retain a managed span, byref-like frame, Roslyn object, compiler object, or runtime registry.

Entities owns component storage, alignment, chunk lifetime, and dependency fences. Each generated job constructs borrowed `Frame<TTrack,TClip>` values only for the synchronous `Execute` call. Writes are visible to later ordered stages. Generated static timeline data is immutable and safe for concurrent reads.

The qualified stable 10,000-row fixture measures 18.006 ns/entity-step, 20 scheduled jobs/step, and 0 main-thread managed B after warmup. Stable Mono and IL2CPP players execute the Burst jobs and pass native leak scans. See the [Unity guide](unity.md) for the exact package and toolchain boundary.

The release gate covers exact behavior receipts, strict 100% production line and branch coverage, warmed 0 B allocation, full-query BenchmarkDotNet results, PMU and assembly evidence, 1/16/256-track code size, package-only JIT and NativeAOT execution, deterministic double-build artifacts, exact UPM contents, stable and preview Unity EditMode/PlayMode, stable Mono and IL2CPP players, Burst symbols, native leak scans, toolchain isolation, and the 300,000-byte source cap.
