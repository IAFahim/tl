# v0.6 — production per-work compilation

v0.6 promotes the successful consumer-fusion shape into `Tl.Runtime` and `Tl.Gen`. Runtime and compiled timelines now share one static `ITrack<TTrack,TClip,TInput,TResult>` contract. The engine resolves each active track and blend once, then invokes the consumer operation directly with typed values and movement state.

The former `Tracks<TTrack,TClip>`, `TrackWork<TTrack,TClip>`, compiled-view interfaces, resolved-blend scratch API, and separate compiled consumer implementation are removed. This is a pre-1.0 breaking API change.

Compiled authoring is now a named declaration:

```cs
public readonly partial struct PulseTimeline : ITimeline<PulseTrack, PulseClip>
{
    public static void Define(scoped TimelineBuilder<PulseTrack, PulseClip> timeline)
    {
        var pulse = timeline.Track(new PulseTrack());
        timeline.Clip(in pulse, new PulseClip(1f), 0u, 60u);
    }
}
```

The generated half supplies `Duration`, `Loops`, `Start`, `Stop`, `Forward`, and `Backward`. Normal application code calls `PulseTimeline.Forward(...)`. The old `Build(...).Compile()` declaration remains as a compatibility input, but its shim is emitted only when a project actually contains a legacy declaration.

The generator emits independent scalar and span kernels. It folds direction, looping, region structure, work identity, blend shape, and constant payload construction. Timelines with at most 64 generated work sites use fully inline balanced region trees. Larger timelines switch to one direction-specific compact track program shared by scalar and batch entry points. That fallback merges adjacent intervals with identical work and grows with the authored per-track segments instead of duplicating every active work across every cut region. Static abstract `ITrack` operations specialize at the closed result type under the tested JIT and NativeAOT toolchains.

The runtime interpreter keeps the same operation surface. Its retained timeline is one explicitly owned native block. Track and clip types are unmanaged. Work streams directly from immutable tables; a blended clip is one local value, so there is no scratch allocation or persistent work view.

Measured BenchmarkDotNet medians on the Pulse fixture, .NET 10.0.11 and an i9-14900K:

| Operation | Interpreter | Compiled | Change |
| --- | ---: | ---: | ---: |
| Full consumer scalar | 15.340 ns | 4.489 ns | 70.7% lower |
| Full consumer batch 8 | 11.231 ns | 4.104 ns | 63.5% lower |
| Sum consumer scalar | 11.157 ns | 2.473 ns | 77.8% lower |

All measured arms allocate zero managed bytes. The production result does not claim universal 1–2 ns execution. The prior exact-operation batch backend reached 1.195 ns/tick by accepting a smaller consumer language and predictable eight-tick streams. The general production contract retains arbitrary typed operation bodies and complete playback semantics.

Release validation passed 43 core tests and 60 generator tests, the compiled/interpreter parity battery under JIT and NativeAOT, the runtime NativeAOT smoke app, Dispatch edge verification, Algorithms verification, package creation, and a clean package-only consumer. The `src` footprint is 29 files, 177,443 content bytes plus 856 path bytes: 178,299 of the 200,000-byte budget.
