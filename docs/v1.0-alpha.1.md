# v1.0.0-alpha.1

This alpha replaces the homogeneous authoring/interpreter split with one build-time model. A normal C# compilation discovers every eligible partial `ITimeline`, validates its tracks, clips, hooks, and borrowed component contract, then emits the executable timeline kernel. Callers use the generated `Input` and `Output`, a runtime `ushort` ID, and `Timeline.TryForward` or `Timeline.TryBackward`.

The release removes `Timeline<TTrack,TClip>`, `TimelineBuilder<TTrack,TClip>`, `Build`, `Compile`, `InMemory`, `Bind`, `Tracks<TTrack,TClip>`, the four-type `ITrack`, ordinal/count callback arguments, cursors, scratch overloads, and runtime destruction. Compiled definitions live for the process registry lifetime. IDs are never reused.

The new contract supports different track and clip types in one timeline. `Frame<TTrack,TClip>` exposes the authored track, resolved clip, effective tick, movement state, and stable track index. Static track callbacks declare any finite list of `in`, `ref`, and `out` component slots. The generator creates ref-backed contexts, so no object array, boxing, reflection, binding table, or copied ECS component is required during playback.

Generation is automatic after referencing `Tl.Gen.CSharp`. The cache hashes sources, defines, compiler identity, and generator identity. Equal inputs preserve output contents and timestamps. Source lists use a response file, so project size and paths containing spaces do not change the invocation shape.

Code-authored definitions visible during the consuming build are supported. Include and compatible runtime routing currently require all involved timeline definitions in the same compilation. A declaration produced by another C# source generator is not visible to the pre-compilation Tl pass. Runtime topology mutation, arbitrary managed mod loading, cross-language backends, and Unity Burst are outside this alpha. The runtime and generated state are NativeAOT-compatible; Burst needs a separate backend and verification matrix.

On the reference i9-14900K with .NET 10.0.12, the public sequential path measured 1.382 ns/tick for the sum consumer and 2.239 ns/tick for the heterogeneous combat consumer. Public batch-8 measured 1.384 and 2.033 ns/tick. Those are the median of three independent run medians and every arm allocated 0 B. Each hot stream uses one runtime-loaded ID. Random ticks measured separately at 4.854–6.974 ns/tick; many-ID dispatch remains outside this alpha performance claim.
