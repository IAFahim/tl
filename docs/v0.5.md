# v0.5 — deterministic generation and measured specialization

Both NuGet packages advance to `0.5.0`: `Tl.Runtime` and `Tl.Gen`. The existing input/result callback API remains intact. This release packages the reviewed runtime and generator improvements together with a reproducible, isolated consumer-fusion experiment.

## Runtime and generator

- Runtime work slots shrink from 28 to 24 bytes, saving 14.3% of that storage. The layout and native blend behavior have regression tests.
- Generated playback specializes direction. The previous matched comparison measured roughly 6–12% lower batch cost, with a roughly 2% repeated single-tick regression and 45.9% larger combined native forward/backward code. This is a measured tradeoff, not a universal speedup.
- The compile cache identifies exact source membership, source contents, generator dependencies, and owned output contents. Unchanged inputs hit the cache; modified or missing outputs are repaired; removed declarations remove their owned output files. Identical output keeps its timestamp.
- Declaration reading rejects ambiguous or unsupported authoring instead of selecting an unrelated method. It remains a restricted syntax reader, not a semantic incremental Roslyn generator.
- Generator packages include their Roslyn runtime dependencies. Build-tool references are insulated from application NativeAOT publish properties.
- Benchmark history now distinguishes runtime jobs and environment identities. Near-zero timing noise is archived without percentage alerts. The previous alert audit is in [performance-alert-0ef2676.md](performance-alert-0ef2676.md).
- CI enforces a 200,000-byte budget for all `src` file contents plus their relative paths, tests the collector, and checks experimental generation parity under JIT and NativeAOT.

## Migration and ownership

Runtime authoring terminates explicitly: `Timeline<TTrack,TClip>.Build(author).InMemory()` returns the runtime handle. Call `Bind<TInput,TResult>` before NativeAOT dispatch, and call `Timeline.Destroy(id)` once when the native snapshot is no longer used. Construction, binding, and destruction require the documented synchronization; do not destroy a snapshot while another thread is reading it. Handles are not reused and remain subject to the finite registry capacity.

`.Compile()` emits the general generated kernel. It does not automatically fuse arbitrary consumer code. General compiled storage still includes managed arrays, and the experiment does not establish Unity Burst compatibility. Runtime retained snapshot storage is unmanaged; managed authoring and build-time generation remain separate phases.

## Consumer-fusion experiment

The experiment specializes the actual four-track, nineteen-clip Pulse authoring and an explicit ordered floating-point sum consumer. It preserves full playback state, lifecycle errors, overflow timing, and ordered arithmetic, while eliminating views, callback dispatch, unused per-work state, and runtime payload lookup. The default balanced-tree backend carries playback locals across an eight-tick batch. A dense backend trades 7,800 bytes of primitive RVA data for less random-region dispatch work.

Representative medians on one i9-14900K P-core, .NET 10.0.11, 65,536 ticks per invocation:

| Stream and call shape | Interpreter | General compiled | Fused tree |
|---|---:|---:|---:|
| Sequential scalar | 12.885 ns | 19.136 ns | 2.616 ns |
| Sequential batch of 8 | 7.846 ns | 10.471 ns | 1.344 ns |
| Random scalar | 18.629 ns | 27.570 ns | 7.599 ns |
| Random batch of 8 | 15.595 ns | 19.545 ns | 7.483 ns |
| Repeated batch of 8 | 8.761 ns | 12.627 ns | 1.283 ns |

These are matched arms within `wide-v2`, not isolated-call latency. All measured arms allocate zero managed bytes. Dense batches measured 1.401 ns sequential, 6.544 ns random, and 1.549 ns repeated in their separate matched run. Maximal same-region runs lost: 2.844, 9.515, and 4.302 ns respectively; that larger backend is retained as a rejected experiment.

The 1–2 ns target is demonstrated for predictable batches of this supported consumer. It is not promised for general callbacks, random seeks, arbitrary games, NativeAOT throughput, or other CPUs. The generator, benchmark harness, source snapshots, raw JSON, and machine-code evidence live under [benchmarks/FusionHour](../benchmarks/FusionHour/README.md). No new experimental code is in the NuGet runtime API.

## Validation and remaining work

Release validation receipts live in [verification/v0.5](verification/v0.5). The experimental verifier checks 40,868 exact comparisons per backend, including an independent clip-list oracle, both directions, floating-point bit patterns, full playback, boundary ticks, lifecycle errors, and effects before batch failure. The default tree backend also has NativeAOT parity coverage. Generator outputs are compared byte-for-byte across repeated emission.

The next production work is a supported typed operation grammar, an unmanaged shared storage/view boundary, and semantic project-aware declaration discovery. Any promotion must account for its generator and emitted-code bytes within the source budget and preserve the tested arithmetic/effect contract. Compression has no universal smallest-program formula: arbitrary payload information and required observable operations impose workload-dependent bounds. Cache fit must be measured over a working set of many timelines, not inferred from this single fixture.
