# v0.4 — the unmanaged runtime timeline

**Status: implemented.** This document records the unmanaged-boundary rework
of the runtime path: `Timeline<TTrack,TTrack>.Build(static b => {...})`
became authoring syntax only, and its terminal operation — `.InMemory()` —
lowers the authored tracks/clips into ONE native allocation with an
explicit lifetime. The managed registry, managed tables and managed
dispatch caches are deleted, not parked behind a flag.

## 1. The change in one paragraph

v0.3's runtime path compiled a `Build` callback into a managed registry
`Entry` (a class holding `uint[]`/`RegionRow[]`/… managed arrays plus a
typed `Tables` payload object), published through a GC-owned
`Entry?[]` slot array, and dispatched through managed generic static caches
(`BindingCache<TInput,TResult>[]`, `ScratchCache<,,,>[]`). v0.4 replaces the
whole retained representation: the lowering (`RuntimeLowering`, the renamed
successor of `TimelineCompiler`) computes the same tables as before but
emits them into a single 16-byte-aligned `NativeMemory.AlignedAlloc` block,
registers the block in a native slot table (index → `NativeEntry*`,
tombstoned on `Destroy`, indexes never reused), and playback walks the
block through spans over native memory — the span-based `PlaybackCore` is
unchanged; only the bridge that builds the spans was adapted. Per-consumer
`(TInput,TResult)` dispatch lives in a native bind-slot table inside the
block (four inline slots, grown by native reallocation). Construction still
uses managed locals — they are transient and die when `InMemory` returns;
what survives is unmanaged memory and nothing else.

## 2. API

The terminal-operation shape (verbatim signatures):

```csharp
namespace Tl;

public static class Timeline<TTrack, TClip>
    where TTrack : unmanaged, IBlend<TClip>
    where TClip : unmanaged
{
    public static TimelineAuthoring<TTrack, TClip> Build(TimelineBuild<TTrack, TClip> build);
    public static TimelineAuthoring<TTrack, TClip> Build(TimelineBuild<TTrack, TClip> build, TimelineOptions options);
    public static TimelineAuthoring<TTrack, TClip> Build<TSource>(TSource source, TimelineBuild<TTrack, TClip, TSource> build);
    public static TimelineAuthoring<TTrack, TClip> Build<TSource>(TSource source, TimelineBuild<TTrack, TClip, TSource> build, TimelineOptions options);
}

public readonly ref struct TimelineAuthoring<TTrack, TClip>
    where TTrack : unmanaged, IBlend<TClip>
    where TClip : unmanaged
{
    public ushort InMemory(); // lower into one native block, register, return the handle
}

public static partial class Timeline // the hub — signatures unchanged
{
    public const ushort None = ushort.MaxValue;
    public static Playback Start(ushort index, uint at = 0);
    public static Playback Stop(ushort index, in Playback playback);
    public static void Destroy(ushort index);          // frees the block; tombstones the slot
    public static bool IsValid(ushort index);
    public static uint Duration(ushort index);
    public static bool IsLooping(ushort index);
    // Forward/Backward overloads: (ushort, in Playback, in TInput, ref TResult, in uint)
    //   and (…, params ReadOnlySpan<uint> ticks); cursor and scratch variants; stateless
    //   (ushort, in TInput, ref TResult, params ReadOnlySpan<uint>) sampling. Unchanged.
}
```

- `Build(...)` returns a `TimelineAuthoring` **ref struct**: it cannot be
  stored in a field or leaked past the statement that uses it, which is the
  type-system expression of "authoring syntax only". Dropping it creates
  nothing; `.InMemory()` is what makes a timeline exist.
- `.InMemory()` returns the ushort handle every hub call already accepts —
  the ergonomic bridge to the existing API is the terminal operation's own
  return value. ECS can store/pass that handle, or the block address it
  resolves to.
- `TimelineCompiler` no longer exists; runtime lowering is
  `Tl.Authoring.RuntimeLowering` (`Authoring/Lowering.cs`). The name
  `Compile` is free for the compile-time specialization feature; this
  rework deliberately adds no `Compile` method.
- **Constraint change:** `Timeline<TTrack, TClip>` now requires
  `TTrack : unmanaged` (TClip already did). Payload tables are copied into
  native memory, which is only correct for types the GC never needs to see.
  All existing fixtures, tests, the sample and the AOT smoke satisfy this.

## 3. Native layout

One block per timeline (`NativeEntry` header at offset 0, every table
16-aligned after it, empty tables still get a valid block-interior
pointer):

```
[NativeEntry header]   stamp, index, closure id, duration, loops,
                       maxima, table counts, table pointers, binder
                       function pointer, bind-slot directory + spin gate
[RegionStarts]         uint[]          — region cut positions
[RegionRows]           RegionRow[]     — per-region (TrackStart, TrackCount)
[TrackRows]            TrackRow[]      — per active track per region
[ClipRows]             ClipRow[]       — clip index + blend window per row
[ClipEdges]            ClipEdge[]      — true [Start, End) windows
[PayloadMap]           ushort[]        — authored→deduped payload (identity when absent)
[TrackData]            TTrack[]        — authored track payloads
[ClipData]             TClip[]         — clip payloads
[WorkSlots]            WorkSlot[]      — v0.3 materialized slots (one per track row)
[InlineBinds]          NativeBindSlot[4] — bound (TInput,TResult) dispatch
```

- `NativeBindSlot` is `{ int Token; 8 × nint function pointers }`: the six
  hub entry points (forward/backward, cursor variants, stateless samples)
  and the two caller-scratch variants of the pair's bridge, for this
  timeline. Pointers are stored as `nint` and cast back to their exact
  `delegate*` types in the generic contexts that installed them.
- Beyond four pairs, slots go to a separately allocated native array grown
  by copy (8, 16, …) under the entry's native spin gate and freed with the
  block; overflow lookups hold the gate, so growth may free the old array.
- The `Cursor`'s owner is now the native entry address (`nint`), which
  preserves the old identity semantics: a destroyed-and-rebuilt timeline is
  a new entry, and indexes are never reused.

## 4. Lifetime and threading contract

- **Lifetime.** `InMemory()` allocates the block and registers the slot;
  `Timeline.Destroy(index)` tombstones the slot and frees the block (and
  its bind overflow). After `Destroy`, every hub call on the handle throws
  `ArgumentOutOfRangeException`; double `Destroy` throws; the index is
  never handed out again. Two `InMemory()` calls over the same authoring
  produce two independent handles with independent lifetimes.
- **Threading.** Construction, registration, binding and destruction are
  single-threaded or externally synchronized with each other and with
  playback. Playback calls are **read-only over an immutable snapshot** and
  safe from any number of threads concurrently (including mixed
  forward/backward/sampling shapes and the cold auto-bind race, which
  converges under the entry's spin gate). `Destroy` concurrent with an
  in-flight playback on the same index is a use-after-free — the documented
  responsibility of the caller; no managed state can paper over it. The
  registry's slot array grows by copy and retires (never frees) the old
  generation so lock-free playback reads never dangle; total retention is
  bounded by geometry (all retired generations together are smaller than
  the live one) and the ushort index cap.

## 5. The managed boundary, honestly

What is still managed, and why it is not timeline state:

- **The `(TInput,TResult)` token counter** (`BindingIds<TInput,TResult>`,
  one machine word per pair): code-identity metadata created by consumer
  code's generic instantiation. It exists whether or not any timeline does;
  timelines merely reference tokens in their native bind tables.
- **The closure identity counter** (one machine word per closed
  `Timeline<TTrack,TClip>` type): same class of thing — it distinguishes
  closures for the scratch overload's ownership check (the job the managed
  `Tables` payload probe used to do).
- **Static machine words of the registry** (`s_slots`, `s_capacity`,
  `s_nextIndex`, spin gates): pointers and counters, not GC objects. The
  index space itself is native memory.
- **Construction transients**: the authoring builder's `List<>`s, the
  lowering's lists/dictionaries and the dedup scratch — all unreachable the
  moment `InMemory` returns (receipt below). The authoring `TimelineBuild`
  delegate and the builder are user code and die with the call.
- **Not retained**: no `Entry` class, no `Tables` payload object, no
  managed arrays, no managed delegate registry state. Those types are
  deleted from the product.

## 6. Receipts

All numbers from this machine, timings pinned to CPU core 10
(`taskset -c 10`), .NET 10, the same session for baseline and challenger.

### 6.1 Unmanaged-ness

Same fixture (3 tracks, 6 clips), 64 full `Build→(InMemory)→Bind→play→
Destroy` cycles after warmup, forced compacting collections around every
measurement, one process per engine, core 10. The managed arm is the frozen
v0.3 sandbox (`benchmarks/Hooks.cs`), the native arm is this tree:

| Signal (64 cycles) | v0.3 managed | v0.4 native |
| --- | ---: | ---: |
| Retained managed heap growth (process-wide) | +896 B (a second 64-cycle interval retained another +1,024 B) | **0 B — and 0 B again on the next interval** |
| Managed bytes allocated (transients, incl. authoring + lowering) | 628 KB | 444 KB |

The managed engine's real cost was never permanent growth — its `Entry`,
tables and cache arrays were garbage after `Destroy` — it was allocator
residue plus ~9.8 KB of GC-tracked garbage per cycle. The native path's
cycles leave the managed heap bit-identical; its construction transients
(authoring `List<>`s, lowering scratch) are the honest remainder, and they
die with the call.

Asserted facts in the suite:

| Receipt | Result |
| --- | --- |
| Steady-state managed heap growth across 64 full cycles (`GC.GetTotalMemory`, exclusive measurement window, retry-guarded) | **0** (≤ 1 KB bound; the managed engine exceeds it) |
| Managed bytes allocated by `Timeline.Destroy` | **0** |
| Managed authoring graph after `InMemory` (WeakReference to the builder state, forced collect) | **dead**, while the native timeline keeps playing |
| Managed bytes allocated per warm playback call (single-tick, batch, cursor, scratch shapes) | **0** (pre-existing v0.2 receipt, re-run against native storage) |
| Old-world managed types surviving (`Timeline.Entry`, `Tables`, `BindingCache`, `ScratchCache`, `Run`, `ScratchRun`, `TimelineCompiler`) | **deleted from the product** — the type-level receipt |

Tests: `tests/Tl.Core.Tests/UnmanagedReceipts.cs` (7 facts), plus the
ported 37; suite total 44 facts green (three consecutive runs), plus
`Tl.Gen.Tests` (4 facts) and the NativeAOT smoke republished and green
(`tests/Tl.Aot`).

### 6.2 Performance (A/B vs the managed v0.3 engine)

Same fixture as the Dispatch sweep (4 tracks, 19 clips, 13 regions, 3
blends, 600 duration, Stay-only consumer through the Playback hub), same
xorshift tick stream, receipts cross-checked identical in setup. Baseline =
the frozen managed v0.3 sandbox (`benchmarks/Hooks.cs`); challenger = this
tree. Bench: `benchmarks/Native` (`dotnet run -c Release`, core 10).

| Arm | v0.3 managed | v0.4 native | Δ |
| --- | ---: | ---: | ---: |
| PlaybackSingle (ns/tick, median) | 23.53 | 17.32 | **−26%** |
| PlaybackParamsFour (ns/tick, median) | 17.46 | 14.77 | **−16%** |

Medians, 16 warmups / 12 iterations / 250 ms; every arm allocates **zero**
managed bytes per operation (MemoryDiagnoser). A repeat run reproduced the
same shape (23.30 / 18.14 / 17.93 / 14.62 — deltas −23% / −19%). The
honest reading: the native block removes the managed hot-path costs
(`Entry` class header + `Entry?[]` double indirection, `ReferenceEquals`
owner checks against managed cache arrays, spans over GC-visible arrays),
and the single-tick shape — a region entry every call — benefits most.
Report artifacts: `benchmarks/Native/results/`.

Context pins from the v0.3 records (same fixture family, core 4, 2026-09-07
sandbox runs): consuming ClipRead 18.09, sweep PlaybackSingle 16.05 — that
pin was the **generated-table shell** (no hub dispatch); the A/B above
measures the **registry hub** path both ways, which is the path v0.4
changed. Cross-session pins are orientation only; the A/B re-measured its
own managed baseline in-session.

## 7. Files

- `src/Tl.Core/Internal/Registry.cs` — `NativeEntry` block header + the
  native slot table (`Register`/`Live`/`IsValid`/`Destroy`).
- `src/Tl.Core/Internal/Binding.cs` — `NativeBindSlot`, the token source,
  `NativeBinding` (lock-free inline lookup, gated install/growth).
- `src/Tl.Core/Authoring/Lowering.cs` — `RuntimeLowering` (was
  `TimelineCompiler` in `Authoring/Compile.cs`, deleted).
- `src/Tl.Core/Timeline.cs` — hub dispatch through native bind slots;
  `Build`/`Bind`/scratch overloads on the typed class; the `Bridge`
  function-pointer bodies wrapping `PlaybackCore` with native-backed spans.
- `src/Tl.Core/Authoring/Builder.cs` — `TimelineAuthoring` (new) beside the
  unchanged authoring builder.
- `src/Tl.Core/Cursor.cs` — owner is the native entry address.
- `PlaybackCore`, `Tracks`, `TrackWork`, `WorkSlot`, `BlendScratch`,
  `GeneratedTimeline`, `ITrackTables`: unchanged.
