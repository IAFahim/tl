# v0.4 — `.Compile()`: compile-time timeline specialization

`.Compile()` means ACTUAL compile-time specialization. `Build(...)` does not
execute at runtime: the generator reads the human-authored timeline
declaration, emits specialized C# for that exact timeline, and Roslyn/JIT/
NativeAOT compile it into machine code with the normal build. No runtime
`Timeline.Entry`, no registry lookup, no payload object, no timeline tables
unless a table is proven optimal. Constants, boundaries, blends, lifecycle
behavior, and dispatch are specialized into code.

This prototype lives in `src/Tl.Gen` (declaration reader + kernel emitter
through the existing Analysis/Model/CSharp pipeline), plays out in
`samples/Compiled` (parity battery + Stopwatch bench mode), is measured by
`benchmarks/Dispatch/CompiledCompare.cs`, and publishes under NativeAOT.

## The authoring grammar (what is Compile-eligible)

```
declaration  := designator '=' timelineBuild '.' 'Compile' '(' ')'
                designator names the kernel: 'Pulse' -> class CompiledPulse
timelineBuild:= [ 'Tl.' | 'global::Tl.' ] 'Timeline' '<' trackType ',' clipType '>'
                '.' 'Build' '(' author ')'
author       := staticSimpleLambda | staticMethodGroup
lambdaBody   := statement*
statement    := 'var' id '=' builder '.' 'Track' '(' payload ')'
              | builder '.' 'Clip' '(' ['in'] trackVar ',' payload
                    ',' uintLiteral [',' uintLiteral | 'start:' uint | 'end:' uint] ')'
              | builder '.' 'Looping' '(' ')'
              | builder '.' 'DedupStorage' '(' boolLiteral ')'      // accepted, ignored
payload      := literal | ('+'|'-') literal | 'default' ['('T')'] | 'new' T '(' payload* ')'
```

Two author forms:

- **inline static lambda** — `Timeline<T,C>.Build(static b => { ... }).Compile()`
- **static method group** — the shared-authoring form the sample uses:

```csharp
public static void Author(scoped TimelineBuilder<PulseTrack, PulseClip> b) { ... }

public static class Decls
{
    // Read by the Tl.Gen compile reader at build time; never executed.
    public static readonly CompiledTimelineInfo Pulse =
        Timeline<PulseTrack, PulseClip>.Build(Authoring.Author).Compile();
}
```

ONE authored method serves both players: the interpreter leg registers it
through `Timeline<PulseTrack, PulseClip>.Build(Author)` at runtime; the
compile reader interprets the same method and emits `CompiledPulse`. The
declaration holder is deliberately never touched, so the declaration site
never executes and nothing registers at runtime — compiled consumers call
the kernel class directly (`CompiledPulse.Forward(in pb, in input, ref
result, tick)`).

Non-eligible sites fail the build with a `TLGENxx` diagnostic that names the
constraint and points at the in-memory interpreter path (drop `.Compile()`,
which has no such constraint):

| code | constraint |
|------|------------|
| TLGEN01 | `.Compile()` must chain directly on `Timeline<T,C>.Build(author)` |
| TLGEN02 | the authoring lambda must be `static` (no captures) |
| TLGEN03 | only Track/Clip/Looping/DedupStorage builder calls are eligible |
| TLGEN04 | track/clip payloads must be compile-time constants |
| TLGEN05 | Clip's first argument must name a local bound by `builder.Track(...)` |
| TLGEN06 | Build's argument must be a static lambda or a resolvable static method group |
| TLGEN07 | two declarations resolved to the same kernel name |
| TLGEN08 | the declaration violates a timeline constraint (windows, overlap) |
| TLGEN09 | only the single-author Build overload is eligible (no source-carrying form) |
| TLGEN10 | tick windows must be uint literals |

## The pipeline

```
sources (@(TlCompileTimeline) items)
  -> Analysis/DeclarationReader.cs    Roslyn-syntax discovery + interpretation + diagnostics
  -> Model.TimelineDefinition         (existing model)
  -> Analysis/RegionAnalyzer          (existing region math — no duplication)
  -> Analysis/WorkSlots.cs            emission-time mirror of PlaybackCore
                                      .MaterializeWorkSlots (no dedup, region-local
                                      blend ordinals)
  -> CSharp/KernelEmitter.cs          CompiledRuntime.g.cs (shared, once) +
                                      Compiled<Name>.g.cs (per declaration)
  -> obj/<cfg>/TlGenCompile/*.g.cs    never committed; content-stable writes
```

Wiring: `build/Tl.Gen.targets`'s `TlGenCompileTimelines` target runs the CLI
in `--compile` mode before `CoreCompile` when a project declares
`@(TlCompileTimeline)` items (`samples/Compiled/Compiled.csproj` shows the
consumption pattern: a `ReferenceOutputAssembly=false` project reference to
Tl.Gen for build order, plus the targets import).

## The generated kernel (abridged, real output)

For the sample declaration (4 tracks, 19 clips, 3 blend pairs, gap at
[11,18), duration 600, looping) the emitter produces (abridged):

```csharp
public static class CompiledPulse
{
    public const uint Duration = 600u;

    private static readonly PulseTrack[] s_trackData = [new PulseTrack(1), ...];
    private static readonly PulseClip[] s_clipData = [new PulseClip(1f), ...];

    // One frozen work blob per non-empty region; region 1 is the t1 blend
    // pair beside two standalone works (entry refs = the pair's OUTER window):
    private static readonly CompiledWorkSlot[] s_works1 =
        [new(0, 0, CompiledWorkSlot.Single, 0u, 7u, 0u, 0u, 0),
         new(1, 1, 2, 3u, 11u, 3u, 4u, 0),
         new(2, 3, CompiledWorkSlot.Single, 3u, 11u, 0u, 0u, 0)];
    ...

    public static Playback Start(uint at = 0) => CompiledPlayback.Mint(at, 0, PlaybackFlags.Started);

    private static Playback Advance<TInput, TResult>(bool backward, in Playback from,
        in TInput input, ref TResult result, ReadOnlySpan<uint> ticks) where ...
    {
        ... // runnable checks, scalar state machine
        foreach (var tick in ticks)
        {
            // Position specialized for Loops=true, Duration=600 as constants:
            // modulo/division by a literal lower to multiply-reciprocal.
            var prevEff = stateTick % Duration;
            var tEff = tick % Duration;
            ... // exact PlaybackCore.Position mirror (wrap shapes, cycles)

            var flags = PlaybackFlags.Started;
            if (tEff == Duration - 1u)
                flags |= PlaybackFlags.LastLoopFrame;

            var works = default(ReadOnlySpan<CompiledWorkSlot>);
            switch (Locate(tEff))        // constant compare tree over the 13 cuts
            {
                case 0: works = s_works0; break;
                case 1: works = s_works1; break;
                ...
                default: break;          // the empty sentinel / clamp target
            }

            if (works.Length != 0)        // empty ticks: no callback
            {
                var tracks = new CompiledTracks<PulseTrack, PulseClip>(works, tEff,
                    scratch, s_trackData, s_clipData,
                    new CompiledMovement(prevEff, backward, wrapped, full));
                if (backward) result.Backward(in tracks, in input, in tEff, ref result);
                else          result.Forward(in tracks, in input, in tEff, ref result);
            }

            stateTick = tick; stateCycles = newCycles; stateFlags = flags;
        }
        return CompiledPlayback.Mint(stateTick, stateCycles, stateFlags);
    }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    private static int Locate(uint tick)
    {
        if (tick < 7u) { ... } else { if (tick < 123u) { ... } ... }  // RegionOf as code
    }
}
```

The shared `CompiledRuntime.g.cs` (one per compilation) carries the view:
`CompiledTracks`/`CompiledTrackWork` mirror `Tl.Tracks`/`TrackWork` exactly —
build-time-materialized slot slices, lazy blend on first `Clip` read through
the consumer's own `IBlend` with the engine's exact factor expression,
positional `Exit`, entry-reference `Enter` — plus the compiled hook pair:

```csharp
public interface ICompiledForward<TTrack, TClip, TInput, TResult> ... : // same shape as IForward
    void Forward(in CompiledTracks<TTrack, TClip> tracks, in TInput input, in uint tick, ref TResult result);
```

A consumer that runs on both paths implements both hook pairs with one-line
bodies over a shared per-work method (`samples/Compiled/Consumer.cs`), so
the parity battery pins the ENGINES to each other, not two consumer copies.

asserts bit-exact equality (floats compared by bits; any divergence exits
non-zero). Verbatim:

The jump battery uses a fixed seed, block-alternating direction, multi-cycle
forward wraps, and backward jumps above and below the previous position.
The battery also passes under NativeAOT.

## The gain receipt

BDN (`benchmarks/Dispatch/CompiledCompare.cs`, the project's Config: Jit +
NoTiering jobs, Median, MemoryDiagnoser; pinned to core 6; three sessions
2026-09-09, archived under `benchmarks/Dispatch/results/v04-compile-20260909/`).
Same authored timeline and consumer on both legs; `OperationsPerInvoke`
1024 (singles) / 600 (batches).

| method | Jit median | NoTiering median | allocated |
|---|---:|---:|---:|
| InterpreterSingleTick (baseline) | 21.6 ns | 29.3 ns | 0 |
| CompiledSingleTick | 17.1 ns | 28.7 ns | 0 |
| InterpreterBatch8 | 14.5 ns | 21.1 ns | 0 |
| CompiledBatch8 | 11.8 ns | 18.9 ns | 0 |
| SumInterpreterSingleTick (light consumer) | 18.2 ns | 25.0 ns | 0 |
| SumCompiledSingleTick (light consumer) | 19.2 ns | 17.8 ns | 0 |

NativeAOT column (`samples/Compiled` published linux-x64, published binary
running the full parity battery then its Stopwatch harness; three runs):
interpreter ~28.1-28.5 ns/tick, kernel ~27.3-27.4 ns/tick.

Honest readings:

- **The kernel saves the interpreter's dispatch layer — ~4-6 ns/tick.** On
  this shape (looping, blends, gaps; consumer doing real per-work work)
  that is 1.2-1.35x; batch arms amortize per-call costs on both sides and
  keep the same edge. Zero allocations on every arm.
- **The floor is the consumer path itself, not dispatch.** With the consumer
  call retained (this prototype's contract), the by-in view handoff plus
  the consumer's walk of up to three works costs ~12-15 ns on this box —
  both engines pay it. The 1.5-3 ns/tick expectation belongs to the frozen
  tier (bake-v3's 1.06 ns receipts bypass the consumer view and accumulate
  directly into a sink — a different contract, deliberately out of scope
  here).
- **Two honest wrinkles.** (1) The light consumer under tiered PGO runs at
  parity (19.2 vs 18.2 ns) — reproducible; under NoTiering the same pair is
  1.4x in the kernel's favor (17.8 vs 25.0). (2) Session-to-session
  variance on this shared 32-core box is up to ±20% (a sibling workload was
  active); the archived sessions bracket the ranges above.
- A packed-primitive frozen-table variant of the work blobs (bake-v3
  pair-table style) was built and measured WORSE (three bounds-checked
  loads + unpack per work beat one 24-byte struct load); it was reverted —
  see the M3 commit for the receipt. User-struct slots cannot ride span
  collection expressions directly (CS9203), so the arrays stay.

## Deviations and future integration

- **Generator packaging**: the generator runs as the Tl.Gen CLI through an
  MSBuild target (the repo's established mechanism), not as a Roslyn
  analyzer assembly — Tl.Gen is a net10.0 executable (Waffle tooling), and
  analyzer assemblies must target netstandard2.0. Discovery is syntactic
  (Roslyn syntax trees), which the grammar above fully determines; an
  analyzer packaging of the same reader/emitter is a follow-up that gains
  IDE squiggles, not capability.
- **Blend values resolve at runtime through the consumer's `IBlend`**, with
  blend windows and factors folded to constants. Folding the blend float
  expressions themselves (bake-v3 did, on generator-known arithmetic) is
  future work requiring verified knowledge of the consumer's Blend body;
  behavioral identity currently pins the user's code as the single source
  of blend truth.
- **`Playback` minting**: `Playback`'s constructor is internal to Tl.Core;
  kernels mint the identical sequential layout with one packed-word
  `Unsafe.BitCast`. A public factory on `Tl.Playback` (runtime surface,
  outside this prototype's allowed files) replaces it.
- **No runtime dispatch hub**: the sample calls the generated static
  directly. Integration with the sibling v0.4 unmanaged registry/hub is
  explicitly out of scope here; the frozen-hub verdicts
  (`benchmarks/Generate/Program.cs`) are the template for that step.
- `DedupStorage` is accepted and ignored (storage dedup is behaviorally
  invisible; the kernel bakes per-region work blobs without dedup, matching
  the interpreter's default options).
- Cursor overloads are not emitted in this prototype (single-tick and
  batch spans cover the parity battery; the persistent-Cursor path is a
  follow-up).
- The blend-scratch `stackalloc` uses the timeline's constant
  `MaxActiveBlends` without the runtime's 4 KB stack budget guard (the
  generator cannot `sizeof` a user clip type; prototype timelines are
  small).
